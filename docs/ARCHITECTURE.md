# Architecture

## Product Shape

Reef is a small declarative cluster deployment system. The operator maintains environment variables and one root seed; Reef derives the full cluster from those inputs, renders deployment artifacts, applies them to remote nodes, and generates subscription files.

The first-phase product shape:

- Use `just` as the only user entry point.
- Use Python for configuration parsing, secret derivation, and file generation.
- Use Ansible for remote deployment, upgrade, and deletion.
- Use Next.js on Vercel to serve private subscription URLs.
- Use Docker-compatible Compose to run the local four-node integration test.

## Repository Layout

```text
.
├── AGENTS.md
├── justfile
├── .env.example
├── ansible/
│   ├── apply.yml
│   ├── delete.yml
│   └── roles/
│       └── reef_node/
├── docs/
│   ├── ARCHITECTURE.md
│   ├── CODING_RULES.md
│   └── DESIGN.md
├── providers/
│   └── <provider-id>/
│       ├── provider.yaml
│       └── node/
├── subscriptions/
│   ├── profiles.yaml
│   ├── render.py
│   ├── upstream.py
│   ├── substore.py
│   ├── substore.mjs
│   └── <profile-template>.j2
├── reef/
│   ├── core.py
│   └── cli/
├── tests/
│   ├── Dockerfile.node
│   ├── integration.py
│   ├── compose.yml
│   └── fixtures/
└── web/
    ├── app/
    │   └── [token]/
    │       └── route.ts
    └── generated/
        └── subscriptions.ts
```

`reef/` contains the core derived model and the thin command entry points used by `justfile`.

`providers/<provider-id>/` is the only place that maintains concrete node-side transport implementation details. Reef loads every provider bundle in deterministic directory-name order.

`subscriptions/` owns the generated subscription profile set and the rendering logic that translates the core route model plus loaded providers into subscription documents.
`subscriptions/upstream.py` fetches and merges nodes from optional upstream Clash
subscriptions and validates the supported Quantumult X conversion inputs.
`substore.py` verifies the pinned official Sub-Store bundle and invokes
`substore.mjs`, an offline adapter around its parser and QX producer. The adapter
receives only node data through stdin and never inherits Reef secrets or prints
converter diagnostics. The subscription templates own all static client
configuration. A generation uses
one merged upstream snapshot for all three profiles and the Web artifacts.
With upstream URLs and no cluster nodes, the core model has no routes or node
secrets; the same subscription and Web rendering path works without deployment.

## Generated Artifacts

These files are generated by tools and are not maintained by hand:

```text
build/
├── ansible/
│   └── inventory.yml
├── nodes/
├── ssh/
│   ├── known_hosts
│   └── reef_id
└── subscriptions/
    ├── client.yaml
    └── <profile-output>

web/generated/
└── subscriptions.ts
```

`build/` and `web/generated/` do not go into git. They may contain remote connection information and subscription content.

## Managed Node Layout

Reef manages only a fixed remote directory and the service files it installs:

```text
/opt/reef/
├── bin/
├── certs/
├── config/
└── .managed.json
```

`/opt/reef/.managed.json` is a non-secret marker. It records only ownership, version, node identity, managed file lists, and render hashes. It must not contain the root seed, node passwords, subscription tokens, or private keys.

System services are declared by the provider manifest. Ansible runs the Reef node apply script, uploads only files that the remote plan reports as missing or drifted, starts or restarts affected services, and deletes managed state through the delete playbook.

## Test Layout

`just test` uses four gateway nodes and one internal echo target:

```text
entries: sg, jp
exits:   us, uk
```

Test containers run real `systemd` and `sshd` without `privileged: true`:

```yaml
cap_add:
  - SYS_ADMIN
tmpfs:
  - /run
  - /run/lock
```

Test-only SSH address mappings live inside `tests/` and are not part of the production configuration model.
